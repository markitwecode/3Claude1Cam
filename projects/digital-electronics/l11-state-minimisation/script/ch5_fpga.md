[c5.lut.1] {mux} Start with a multiplexer, from an earlier lecture. Its select inputs choose one of its data inputs, and pass it to the output. {tie} Now tie each data input to a fixed one or zero. {select} Feed three variables into the select inputs, and out comes the bit stored for that combination. {name} The slides call a multiplexer used like this "a hardware look-up table".

[c5.lut.2] {rom} A read-only memory works the same way. The slides call it "essentially a look-up table". {address} Its input lines form an address, and out comes the word stored at that address. {nosimp} To make a logic function with one, you just store its truth table, with no simplification needed.

[c5.lut.3] {four} An F-P-G-A's lookup table is the same idea, made small. {cells} A four-input table has sixteen locations, one for each combination of its inputs, and each holds one bit. {any} Store a function's truth table there, and the table becomes that function. {count} There are over sixty-five thousand functions of four variables, and every one of them fits, in the same sixteen bits.

[c5.lut.4] {sync} Here's an example. Take the synchroniser's dee one. Its inputs, S one, S zero, ee and ar, form the address. {kmap} Its bits are the values from Lecture ten's K-map, put in counting order. {rows} With the current state at zero zero, all four bits are zero. At zero one, only the last is one. At one zero, they read one, one, zero, one. {unused} The unused state, one one, was all don't cares. But every location must hold a bit, so it stores what the equation gives.

[c5.lut.5] {lookup} Now look one up. Sight is zero one, and with ee and ar both one, the address is zero one one one. {hit} That location holds a one, so on the next edge, S one becomes one. The machine moves to Sync, exactly as the diagram says.

[c5.config.1] {byhand} Nobody sets all those bits and switches by hand. {hdl} You describe the circuit you want, usually in a hardware description language, such as Verilog, or as a schematic. {synth} Then a synthesis tool works out the contents of every lookup table, the setting of every multiplexer, and the routing. {download} That configuration is downloaded to the F-P-G-A. {lab} It's the same idea as the lab's compiler for the Gal, on a much larger scale.

[c5.config.2] {sram} In Xilinx devices, the configuration sits in static RAM, which makes them easy to reprogram. {volatile} But static RAM loses its contents when the power is removed. {powerup} So the configuration is loaded again every time the system powers up, either from a computer, or from a memory chip on the board that keeps its contents without power.
